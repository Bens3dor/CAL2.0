# CAL2.0

## Descripción
"Elegi 'Calculator'(Calculadora) porque resuelve la necesidad de contar con una herramienta accesible en línea para realizar cálculos matemáticos cotidianos (suma, resta, multiplicación y división) de forma inmediata."
 
## User Stories
- Como usuario, quiero ver una pantalla que muestre los números ingresados y los resultados de las operaciones.
- Como usuario, quiero hacer clic en los botones de los dígitos (0-9) para ingresar los números.
- Como usuario, quiero hacer clic en los botones de las cuatro operaciones básicas (+, -, ×, ÷) para realizar cálculos.
- Como usuario, quiero un botón de igual (=) para ejecutar y visualizar el resultado de la operación.
- Como usuario, quiero un botón para limpiar/borrar la pantalla (C / AC) para reiniciar mis cálculos o corregir errores.
- Como usuario, quiero poder ingresar un punto decimal (.) para realizar operaciones con números no enteros.
 
## Metodología
Enfoque ágil ( Kanban) — "Elegi una metodología ágil (Kanban) porque,  permite trabajar mediante un proceso de prueba y error e iteraciones cortas, lo cual nos ayuda a entender y corregir el código conforme avanzamos. Además, las User Stories de la Calculadora se prestan para construir la aplicación por partes (primero la interfaz y luego las operaciones), y el uso del tablero en GitHub Projects nos facilita visualizar y repartir el progreso del equipo en tiempo real."

## Justificación 
El proyecto CAL2.0 (migrado desde la versión inicial SOLI-DO) nace ante la necesidad de proveer una herramienta de cálculo accesible, precisa e intuitiva para resolver operaciones matemáticas cotidianas de forma inmediata.
La elección de una calculadora básica como caso de estudio se justifica por su capacidad para estructurar un flujo claro de captura, procesamiento y despliegue de datos.

Para abordar su construcción bajo un margen de tiempo acotado, se adoptó la metodología ágil Kanban. Aunque inicialmente el proyecto planteaba una dinámica grupal, decidí continuar y ejecutar la metodología de manera individual. Esto me permitió retomar el flujo desde cero, corregir los errores identificados en el proceso anterior y comprender a fondo cada uno de los conceptos explicados por el docente.

Este enfoque se justifica por tres razones principales:

Modularidad: Permite segmentar el desarrollo partiendo de las Historias de Usuario, abordando primero la maquetación de la interfaz y posteriormente la lógica funcional (operaciones, borrado y control de excepciones).

Adaptabilidad: Favorece ciclos cortos de evaluación y ajuste de código mediante iteraciones continuas y control de versiones, reduciendo el impacto de eventuales fallos.

Gestión transparente e individual: A través de herramientas de control visual como GitHub Projects y la vinculación de Issues con commits (Closes #X), logré organizar mi tiempo, monitorear el avance de manera autónoma y asegurar la trazabilidad completa del código en tiempo real.
